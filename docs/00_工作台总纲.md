## 1. 一句话定位

## 2. 核心原则（所有设计决策的标尺）

1. **决策主线 > 内容支线**：工作台不是内容工厂。内容流水线（评价采集等）是供料系统，主线是经营诊断→行动建议→人拍板→效果复盘
2. **AI做提案、人做决策**：不追求100%无人值守；关键判断点必须有人介入且留痕
3. **3个工具用透 > 10个工具摆烂**：Coze（大脑/造工具）+ WorkBuddy（手脚/本地管道）+ 飞书（数据底座），不轻易引入新工具
4. **数据先于AI**：口径不清不接AI（什么叫爆款/异常/高转化，先写定义）
5. **唯一事实源**：每类数据只有一个权威来源，其余都是副本/视图
6. **小步快跑**：MVP优先，先手工跑通再自动化，细节步子小、动作快
7. **经验必须沉淀**：每次跑通的流程→SOP元文档；每个重要认知→认知卡片

## 3. 架构（落地版五层）

```
第5层 成长引擎：认知卡片 + 周复盘 + 策略模板库 + 失败案例库
第4层 AI雷达：平台政策/竞品/爆款/AI工具动态 → AI筛选 → 只推高优先级
第3层 场景应用：
      【主线】经营诊断Agent（MVP在建）：数据→异常→建议→人拍板→追踪
      【支线】评价采集流水线（✅已验证=模板0）、内容生产工厂（规划中）
第2层 能力编排：Coze=大脑（推理/分析/多Agent）；WorkBuddy=手脚（本地自动化/UI操作）
第1层 信息底座：飞书多维表格=结构化数据事实源；本地+XBserver=素材文件；元资料见§5
```

**场景标准骨架（模板0已验证）**：飞书做任务源+结果台账 → Agent/WorkBuddy做处理管道 → 本地+镜像双存储 → 状态机可视化 → 回传飞书。新场景照此骨架生长。

## 6. AI交接包（给新AI的启动指引）

任何AI首次参与本工作台，按顺序读：
1. 本文档（`00_工作台总纲.md`）——全貌、原则、分工
2. `01_元资料规范.md`——文档怎么写、存哪、怎么更新
3. `认知卡片001_评价采集工作台.md`——已验证模板0的完整拆解
4. `AI工作台案例调研_report.md`——15个标杆案例与设计依据
5. 飞书多维表格（建成后）——结构化数据现状

**交接铁律**：动手前先确认事实源；产出必须按元资料规范落盘；数字/功能描述必须有依据，禁止虚构。

## 7. 术语与口径锚（持续补充）

- **异常**：核心指标日环比/周环比波动 >20%
- **爆款**：口径待红光定义（建议：点击率≥7-8% 且 转化率≥3%，参考7月素材沉淀）
- **跑量素材门槛**：千川3s留存≥35%过冷启动；单条卖点≤2个
- **模板0**：评价采集工作台（已验证场景闭环，见认知卡片001）
- **MVP**：经营诊断Agent最小闭环（见§8）
