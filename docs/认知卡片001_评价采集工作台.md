# 认知卡片 001：商品评价采集工作台（WorkBuddy 造）

> 成长引擎 · 第一张认知卡片
> 记录日期：2026-08-29 ｜ 状态：已验证上线 ｜ 分类：场景模板 / 内容生产
> 载体：WorkBuddy 本地工作台（http://127.0.0.1:8518/）+ 飞书多维表格 + XBserver 镜像

---

## 一、出发点（它为什么被创造）

评价是电商素材富矿：买家秀图片 + 真实买家文案，可反哺详情页、主图、短视频脚本、痛点研究（陪跑项目已验证"商品评价研究用户痛点和功能卖点"的思路）。

但手工采集的痛点：
- 逐个商品翻淘宝/京东评价，人工存图、复制文案、按品牌归类
- 每次打开平台都要扫码登录，批量操作时登录态是最大卡点
- 人力全耗在重复劳动上，采集完的素材散落各处，无法复用

本质问题：**确定性、重复性、流程化的采集劳动，应该交给管道自动完成。**

## 二、优秀点（核心优势与设计思路）

| 设计 | 价值 | 可借鉴度 |
|---|---|---|
| 登录态预登录一次（Cookie 沉淀本地，支持从 Edge 复制），批量免扫码 | 解决平台自动化最大卡点，是工具能跑起来的前提 | ⭐⭐⭐ 所有涉及平台采集的场景通用 |
| 飞书双向闭环：导入商品档案 ← → 回传采集结果 | 飞书既是任务源又是结果台账，数据不落一地 | ⭐⭐⭐ 工作台标准骨架 |
| "素材库为唯一真源"，采完即按品牌自动整理归类 | 有数据治理意识，杜绝散落文件 | ⭐⭐⭐ |
| 状态机可视化：预登录 → 等待链接(waiting_url) → 采集中(running) → 完成/失败 | 任务进度透明，失败可定位 | ⭐⭐ |
| waiting_url 状态 + 链接后补 | 容错设计：档案可先建、链接后补，不卡流程 | ⭐⭐ |
| 本地存储 + XBserver 一键镜像双存储 | 生产与备份分离，支持共享 | ⭐⭐ |
| 参考图对照 + "已采用"标记 | 采集不是终点，采用才是——有素材消费闭环意识 | ⭐⭐⭐ |
| 5 模块界面：概览/新建采集/采集记录/素材库/设置 | 轻量本地 Web 工作台，不依赖重型系统 | ⭐⭐ |

## 三、衔接性（与工作台其他模块的关系）

- **这是工作台场景应用层的第一个已验证模板（模板0）**，骨架为：
  `飞书导入任务 → 自动处理管道 → 结果落盘（本地+镜像）→ 回传飞书台账`
- 与"内容生产"维度直接同构：4 个执行切入点中的内容生产链路，照此骨架生长
- 验证了 AISO 体系判断：**WorkBuddy 适合"确定性管道"类工作流**（流程化、严格输出）
- 上游衔接：飞书商品档案（品牌/平台/货号/链接/参考图）
- 下游待衔接：评价文案 AI 提炼（痛点词/卖点词/场景词）→ 反哺商品元数据表 + 脚本库

## 四、使用法（操作要点）

1. 飞书表格维护商品档案（品牌/平台/货号/链接，链接可后补），工作台一键导入
2. 首次使用预登录淘宝/京东（扫码一次，Cookie 沉淀本地；失效可从 Edge 刷新登录态）
3. 设置图片存储根目录 + XBserver 镜像路径
4. 批量发起采集，状态机自动流转，失败可单条"更新采集"重试
5. 采集完成后一键"整理归类"（materials→品牌目录）
6. 素材库浏览/评价组视图，标记"已采用"
7. "回传结果到飞书" + "同步到 XBserver"收尾

## 五、升级路（用熟之后的进阶方向）

- [ ] 评价文案接 AI 分析 → 自动提炼高频痛点词/卖点词/场景词 → 反哺商品元数据（21字段体系）和短视频脚本库
- [ ] 评价图片接图像识别 → 自动打场景/构图/人群标签
- [ ] 同模式复制到竞品视频素材采集（陪跑项目素材中控台：蝉妈妈素材 → 链接 → 下载 → 归类）
- [ ] 采集结果与"已采用"标记回流，形成素材采用率数据，反哺采集策略

## 六、借鉴值（对整个工作台的启发）

1. **模板复用价值大于工具本身**：后续所有场景（数据分析、素材库、AI雷达）都应照"飞书做源和台账 → WorkBuddy/Agent 做管道 → 本地+镜像双存储 → 状态机可视化"的骨架长，不另起炉灶
2. **先跑通闭环再谈体验**：这个工作台没有华丽 UI，但每个环节都在真实工作流里，这才是"执行层提效"的样板——纠正了"先做页面再补内容"的老路
3. **登录态/权限类卡点要前置解决**：任何自动化场景，先验证"能不能稳定访问"，再设计流程
4. **"唯一真源"原则**：每类数据必须指定唯一归属地（素材→素材库，结构化数据→飞书），其余都是镜像
5. **容错设计决定可用性**：链接可后补、失败可重试、状态可观测——管道类工具的标配
